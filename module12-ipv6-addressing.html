    Why do we need IPv6?

    The address jar
    is empty

    Book section 12.1.1

    In plain English

    Every device on the internet needs an address, like a phone number. IPv4 only has about 4.3 billion, and we ran out of fresh ones. IPv6 has 340 undecillion (a 340 followed by 36 zeros). It also fixes some IPv4 headaches along the way.

    🩹 NAT was duct tape

    Private addresses plus NAT slowed the shortage. But NAT confuses some apps, adds delay, and makes direct device-to-device (peer-to-peer) connections harder.

    📱 Phones led the way

    With so many mobile devices, mobile providers were some of the first to move to IPv6.

    🌡️ The Internet of Things

    Cars, appliances, medical gear, and sensors all want to be online too.

    Tap everything in your home or pocket that connects to the internet

    IPv4 and IPv6 living together

    Awkward roommates,
    but it works

    Book section 12.1.2

    In plain English

    There's no "switch day" where the internet flips to IPv6. Both will exist for years, so we use three bridges to get from one world to the other.

    🗣️ Dual stack

    The device speaks both languages: IPv4 and IPv6 at the same time.

    ✉️ Tunneling

    An IPv6 packet rides inside an IPv4 packet, like an envelope inside an envelope.

    🧑‍🏫 Translation (NAT64)

    A translator swaps IPv6 packets for IPv4 packets and back.

    Tunneling and translation are temporary bridges. The goal is native IPv6 from start to finish.

    Meet an IPv6 address

    8 chunks. 32 digits.
    128 bits.

    Book section 12.2.1

    In plain English

    An IPv6 address is 128 bits written in hexadecimal. Each hex digit stands for 4 bits, so that is 32 hex digits. We split them into 8 chunks of 4 digits, separated by colons. The course calls one chunk a hextet (16 bits). Writing all 32 digits is called the preferred format.

    Case doesn't matter in IPv6.

    Hex digit decoder

    Hex counts 0 to 9, then a to f. Tap a digit.

    Shrinking an address: two rules

    Same address.
    Fewer digits.

    Book sections 12.2.2 and 12.2.3

    In plain English

    Full addresses are long, so we shorten them. Rule 1 is about zeros at the front of a chunk. Rule 2 squashes a run of all-zero chunks into ::. You may only use :: once, or nobody could tell how many chunks it hides.

    Rule 1: Drop leading zeros

    01ab → 1ab, 00ab → ab, 0000 → 0. Never drop zeros at the end: ab00 is not ab.

    Rule 2: One :: only

    Replace one run of all-zero hextets with ::. If there are two runs, squash the longest. If they tie, squash the first.

    Spot the mistake

    Each card shows a full address and someone's shortened version. Judge it.

    Three kinds of addresses

    One, many,
    or nearest

    Book section 12.3.1

    In plain English

    Think about how you send messages. Unicast is a text to one friend. Multicast is a group chat. Anycast is calling a store chain and getting the nearest branch. IPv6 has no broadcast. The "all-nodes" multicast group does that job instead.

    Unicast

    One sender, one receiver. Identifies one interface.

    Multicast

    One packet to a whole group of devices.

    Anycast

    One address shared by several devices. The nearest one answers. (Just know the idea.)

    Prefix length (no more masks!)

    Just a slash
    and a number

    Book section 12.3.2

    In plain English

    IPv6 doesn't use dotted subnet masks. The prefix length is a slash and a number from 0 to 128. It says how many bits, counting from the left, name the network. The rest name the device. Almost every LAN uses /64, because SLAAC builds a 64-bit interface ID.

    Violet = network bits. Pink = device bits.

    Find the network

    Write the network prefix for this address. Keep the network bits, make the rest zeros, and add the slash.

    Global, link-local, and unique local

    Who can
    reach me?

    Book sections 12.3.3 to 12.3.7

    In plain English

    Most IPv6 interfaces have two unicast addresses. The GUA (global unicast address) is the public, internet-routable one. The LLA (link-local address) only works on the same link (subnet), and routers never forward it. Every IPv6 interface must have an LLA. A GUA is optional.

    GUA

    Starts with 2 or 3 (2000::/3). Public, like a public IPv4 address.

    LLA

    Starts fe80 to febf (fe80::/10). Same link only. Often the router's default-gateway address.

    Unique local

    fc00::/7. For inside a site. Not routed on the internet. Not commonly used yet.

    Examples in books use 2001:db8::/32. It's reserved for documentation.

    Inside a global unicast address

    Street, building,
    apartment

    Book sections 12.3.5 and 12.3.6

    In plain English

    A GUA has three parts. The global routing prefix is the part your ISP gives you (the street). The subnet ID is the part you control (the building). The interface ID is the device itself (the apartment). With a /48 from your ISP and a /64 for each LAN, you get a 16-bit subnet ID and a 64-bit interface ID.

    How many subnets do I get?

    Bonus fact: unlike IPv4, you can assign the all-zeros and all-ones interface IDs, because there is no broadcast. (The all-zeros one is reserved for routers.)

    Setting addresses by hand

    Hands on
    the keyboard

    Book sections 12.4.1 to 12.4.3

    In plain English

    IOS commands for IPv6 look like the IPv4 ones with ipv6 in place of ip. The IPv6 command is ipv6 address address/prefix-length, with no space before the slash. To pick your own link-local address, add the word link-local on the end.

      How a device asks for help
      Ask the router.
      It answers.
      
  
      Book section 12.5.1
      
  
      In plain English
      Most devices get their global address automatically. A new device can ask with a Router Solicitation (RS). A router answers with a Router Advertisement (RA). These are ICMPv6 messages. The RA is a suggestion: the device's operating system makes the final call.
      
  
      
  
      
  
      What's inside an RA?
      • The network prefix and prefix length (which network you're on)
      • The default gateway (the router's own link-local address)
      • DNS server addresses and a domain name
      A router must be turned into an IPv6 router with ipv6 unicast-routing (it's off by default) before it sends RAs.
      
  
      

      



      
  
      Three ways to get a global address
      Who tells
      me what?
      
  
      Book sections 12.5.2 to 12.5.4
      
  
      In plain English
      The RA message tells your device which of three methods to use. Method 1 (SLAAC): "I have everything. Build your own address." Method 2 (SLAAC + stateless DHCPv6): "Build your own address, but ask a server for extras like DNS." Method 3 (stateful DHCPv6): "I'm your gateway, but ask the server for your address and everything else." (Stateful works like IPv4 DHCP: the server keeps a list.)
      
  
      
    
      Who provides it?
      
    
      For each method, choose where the device gets each piece of information.
      
    
      
    
      
    
      
  
      
  
      The default gateway only ever comes from the RA message. A DHCPv6 server never provides it.
      
  
      

      



      
  
      Building the interface ID
      EUI-64 or
      random?
      
  
      Book sections 12.5.5 to 12.5.7
      
  
      In plain English
      With SLAAC the router gives the prefix, and the device must invent the last 64 bits. There are two ways. EUI-64 builds it from the device's MAC address: split the MAC in half, put fffe in the middle, and flip the 7th bit. The other way is a random 64-bit number, which protects privacy because the MAC can't be traced.

        EUI-64 or random?
        
    
        Hint: look for fffe in the middle of the interface ID.
        
    
        
  
        
  
        Windows has used random interface IDs since Windows Vista. To make sure an address isn't already taken, a device runs duplicate address detection (DAD), like asking "does anyone else have this?"
        
  
        

        



        
  
        Link-local addresses and checking your work
        Read the output
        like a pro
        
  
        Book sections 12.6.1 to 12.6.4
        
  
        In plain English
        A device builds its own link-local address using fe80:: plus an interface ID (EUI-64 or random). Windows usually uses the same method for its global and link-local addresses. A Cisco router makes an LLA by itself as soon as you give an interface a GUA, using EUI-64. That address is long and hard to remember, so people often type routers' LLAs by hand, like fe80::1:1. Three commands help you verify: show ipv6 interface brief, show ipv6 route, and ping.

        Multicast addresses
        Group chat
        rules
        
  
        Book sections 12.7.1 to 12.7.3
        
  
        In plain English
        IPv6 multicast addresses start with ff00::/8 and are only ever destinations. Two well-known groups: ff02::1 (all nodes, everyone on the link) and ff02::2 (all routers). The 2 means "stay on this link". A solicited-node multicast address is a special one that lets the network card ignore messages that aren't for it, so the CPU isn't bothered.

        Subnetting is just counting
        No binary.
        Promise.
        
  
        Book sections 12.8.1 and 12.8.2
        
  
        In plain English
        IPv4 subnetting means borrowing bits. IPv6 was built for subnets: there's a dedicated subnet ID hextet. With a /48 from your ISP, that's 16 bits, so you can make 65,536 /64 subnets. To get the next subnet, just count up in hex: 8, 9, a, b, c, d, e, f, 10, 11...

        You're the
        network admin
        
  
        Book sections 12.8.3 and 12.8.4
        
  
        In plain English
        Your ISP gave you 2001:db8:acad::/48. This network needs five subnets: four LANs and the link between the two routers. Pick a subnet ID for each. Even the router-to-router link gets a /64, because IPv6 doesn't need to save addresses.
