11.1 IPv4 Address Structure

32 bits, four octets

An IPv4 address is 32 bits, grouped into four 8-bit octets and written in dotted decimal (each octet 0 to 255). Each bit in an octet has a place value:

Try it: octet converter

Tap the bits, or type a number.

Decimal:   Binary: 00000000

Network portion, host portion, subnet mask

The network portion says which network you are on. The host portion says which device you are. The subnet mask splits the address: 1s = network, 0s = host. The prefix length counts the 1s (255.255.255.0 = /24).

Finding the network address: logical AND

1 AND 1 = 1. Every other pair = 0. AND the address with the mask to get the network address.

Try it: AND explorer

Formula: usable hosts = 2h - 2 (h = host bits). Network address = host bits all 0. Broadcast = host bits all 1.

Public addresses are unique on the internet (handed out by RIRs, then ISPs). Private addresses are for inside networks and are translated by NAT before going to the internet.

11.4 Network Segmentation

On one big flat network, every broadcast reaches every device. A router does not forward broadcasts, so each subnet is its own broadcast domain.

  • Less broadcast traffic, better performance
  • Security: apply rules between subnets
  • Easier troubleshooting: problems stay in one segment
  • Group by location, function/department or device type

Try it: who hears the broadcast?

Click a device to make it send a broadcast. Devices that receive it show a check mark.

Remember: devices in different subnets can only talk through a router (or Layer 3 switch). A DMZ is a separate subnet for internet-facing servers.

11.5 and 11.6 Subnetting a Network

To subnet, borrow bits from the host portion. The prefix gets longer.

Subnets = 2n (n = bits borrowed)
Usable hosts = 2h - 2 (h = host bits left)
Block size = 256 - mask value in the interesting octet

Example: split 192.168.1.0/24 into 4 subnets. 4 = 22, so borrow 2 bits: /26 (255.255.255.192), block size 64. Subnets: .0, .64, .128, .192. Each has 62 usable hosts.

Try it: subnet explorer

/16 and /8: same idea, but the borrowed bits fall in the 3rd or 2nd octet. Example: 172.16.0.0/16 with /20: 16 subnets, block size 16 in the 3rd octet (172.16.0.0, 172.16.16.0, 172.16.32.0 ...), 4,094 hosts each.

5 steps: 1) bits to borrow? 2) new prefix? 3) block size? 4) list subnets by adding the block size 5) broadcast = one before the next network.

11.7 Subnetting to Meet Requirements

Requests sound like: "I need 5 subnets with 25 devices each." You must meet both numbers.

Two checks: smallest n with 2n ≥ subnets, and smallest h with 2h - 2 ≥ hosts. Then n + h must fit in the host bits you started with.

Try it: requirements checker

Not always possible: 12 subnets and 20 hosts from one /24 needs 4 + 5 = 9 bits, but a /24 only has 8 host bits.

11.8 Variable Length Subnet Masks (VLSM)

Using one mask everywhere wastes addresses (a /26 on a 2-host WAN link wastes 60). VLSM = subnetting a subnet so each segment gets a block that fits.

Steps: 1) list segments and hosts 2) sort largest to smallest 3) choose the smallest block that fits (2h - 2 ≥ hosts) 4) assign each starting at the next free address 5) record it in a table.

Try it: VLSM builder

Common mistake: placing small subnets first. It leaves gaps and can make large subnets impossible to place.

11.9 and 11.10 Structured Design and Packet Tracer Practice

Plan first, configure second. Count hosts per segment (with room to grow), use a consistent pattern (for example the first usable address on each LAN is the router gateway), keep an addressing table, and verify with ping.
